# 角色、权限与用户设计

状态：已议定  
记录日期：2026-11-05

## 1. 设计结论

- 采用“用户 → 单一角色 → 固定权限集合”的轻量模型；
- 权限目录由代码和数据库迁移维护，管理员只调整角色与权限的映射；
- 不提供单用户权限覆盖、多角色叠加或任意权限编辑；
- 后端负责权限、内容归属和账号状态校验，前端仅负责呈现可用操作；
- 权限、角色、封禁和内容删除等管理操作写入审计日志。

## 2. 角色与账号状态

### 角色

| 角色 | 用途 |
| --- | --- |
| 管理员 | 管理用户、角色权限、内容和审计记录 |
| 普通用户 | 管理本人照片、作品集、评论和玩家档案 |
未登录访客只读访问公开内容，不建立数据库账号，也不是数据库角色。

### 账号状态

| 状态 | 含义 |
| --- | --- |
| `pending` | 注册申请待审核 |
| `active` | 正常使用 |
| `rejected` | 注册申请被拒绝 |
| `banned` | 已封禁 |

封禁作为账号状态实现，不作为角色。封禁时保留原角色、撤销现有会话；解封后恢复为 `active`。系统必须防止管理员封禁自己或移除最后一个管理员。

## 3. 注册与审核

1. 访客自行提交用户名、密码、显示名称、Minecraft 玩家名和申请说明；
2. 系统预分配普通用户角色并设为 `pending`，审核前不能登录或取得角色权限；
3. 管理员批准后调整为 `active`；
4. 管理员拒绝后调整为 `rejected`，并记录原因；
5. 不再使用管理员邀请码。

注册安全规则：

- 同一 IP 和同一账号标识在每个限流窗口内最多提交 5 次；窗口时长在实施时统一配置；
- 密码长度至少 8 位，且至少包含一个字母和一个数字；
- 校验用户名与 Minecraft 玩家名重复；
- 使用轻量蜜罐字段；出现实际滥用后再考虑验证码。

## 4. 权限清单

| 分组 | 权限代码 | 中文名称 | 范围 |
| --- | --- | --- | --- |
| 评论 | `comment.create` | 发表评论 | 本人 |
| 评论 | `comment.withdraw.own` | 撤回本人评论 | 本人 |
| 评论 | `comment.delete.any` | 删除评论 | 管理员，软删除 |
| 照片 | `photo.create` | 上传照片 | 本人 |
| 照片 | `photo.update.own` | 修改本人照片 | 本人元数据，不替换已发布原图 |
| 照片 | `photo.publish.own` | 发布本人照片 | 本人 |
| 照片 | `photo.archive.own` | 归档本人照片 | 本人 |
| 照片 | `photo.delete.any` | 删除照片 | 管理员，软删除 |
| 作品集 | `story.create` | 创建作品集 | 本人 |
| 作品集 | `story.update.own` | 修改本人作品集 | 本人 |
| 作品集 | `story.publish.own` | 发布本人作品集 | 本人 |
| 作品集 | `story.archive.own` | 归档本人作品集 | 本人 |
| 作品集 | `story.delete.any` | 删除作品集 | 管理员，软删除 |
| 玩家档案 | `profile.manage.own` | 管理本人玩家档案 | 本人 |

原图下载面向所有访客公开，不进入权限系统。管理员角色额外拥有用户审核、角色分配、封禁、角色权限管理和审计查看能力。

## 5. 后台管理界面

- “注册审核”：查看申请信息，批准或填写原因后拒绝；
- “用户管理”：使用中文角色名分配角色，执行封禁与解封；
- “角色与权限”：按评论、照片、作品集、玩家档案和系统管理分组，以简洁中文名显示权限；
- 权限代码只作为开发标识，不作为主要界面文案；
- 系统角色名称固定，第一阶段不支持任意创建、删除或重命名角色。

## 6. 数据关系

```text
users.role_id → roles.id
roles ← role_permissions → permissions
users.status → pending | active | rejected | banned
```

核心表包括：

- `users`：账号、单一角色、状态及封禁信息；
- `roles`：固定系统角色及中文名称；
- `permissions`：固定权限代码、中文名称、说明和分组；
- `role_permissions`：角色与权限关联；
- `audit_logs`：审核、角色、封禁、删除等操作记录。
