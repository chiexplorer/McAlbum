# McAlbum 需求描述

## 1. 产品定位

McAlbum 是 Minecraft Fabric 纯净生存服务器的轻量“世界档案馆”，用于长期保存和展示服务器简介、照片、主题作品集与玩家档案。它不是通用服务器面板，也不承担在线状态、经济、排行或运维管理。

项目只记录一个持续运行的世界，不建模周目。地点和事件可以作为照片说明或作品集正文中的自然语言出现，但当前不作为独立实体、页面、权限模块或数据库表维护；未来只有在真实内容规模证明值得时才重新评估。

## 2. 内容范围

### 2.1 服务器简介

- 世界定位、版本和共同游玩原则；
- 具有代表性的封面照片和近期照片；
- 通往相册、作品集和玩家志的清晰入口。

### 2.2 照片档案

- 标题、说明、拍摄日期、替代文本和主题标签；
- 响应式图片、焦点裁切、懒加载与大图查看；
- 已登录玩家的异步评论；
- 与相关玩家、作品集建立轻量关系；
- 照片稳定 ID 由系统首次保存时自动生成。

### 2.3 主题作品集

作品集把多张照片编排为可阅读的专题。支持文字、宽幅图片、图片网格、图文并排和玩家引语等内容区块。

- 作品集稳定 ID 由系统生成；
- 区块 ID 是排序和后续编辑所需的内部标识，由系统生成并维护；
- 编辑者通过照片标题下拉选择封面与区块图片，不输入媒体 ID；
- 日期、地点和事件背景直接写入标题、摘要、正文或图片说明，不额外维护结构化实体。

### 2.4 玩家志

- 玩家名称、简介、加入日期、头像和代表作品；
- 账号与玩家档案分离；
- 玩家可以维护自己的公开资料，私密档案不会进入公开投影。

## 3. 浏览结构

公开导航保持四个主要入口：世界首页、相册、历史作品集、玩家志。详情内容拥有稳定、可分享的 URL。筛选状态进入 URL，返回和刷新后保持一致。

地点档案页、独立事件页、时间线路由和地图不在当前范围内。作品集本身承担历史叙事，照片标签承担轻量发现。

## 4. 账号、权限与状态

- 访客：只读取已发布公开内容；
- 普通用户：维护本人玩家资料，并按能力投稿照片、作品集或评论；
- 管理员：审核注册申请、管理角色权限与账号封禁，并处理违规评论或内容。

固定能力按评论、照片、作品集、玩家档案和系统管理分组，通过角色统一授予；不提供逐用户权限覆盖或通用 ACL。注册采用“自行申请、管理员审核”，封禁作为账号状态而不是角色。

照片和作品集保留既有状态兼容，日常流程简化为 `draft`、`published`、`archived`，管理员删除时进入 `deleted`。关键权限变更、发布、归档、封禁和内容删除需要审计记录。

## 5. 体验与视觉

视觉方向为“世界测绘档案 + 社区摄影集”：温和纸张色、克制的档案标记、Minecraft 截图作为主体。避免像素菜单仿制、过度动画和重复卡片装饰。

- 移动端重新编排内容，不只是缩小桌面版；
- 所有关键操作支持键盘；
- 遵循 `prefers-reduced-motion`；
- 图片声明尺寸和替代文本，首屏外默认懒加载；
- 不以颜色作为状态的唯一表达方式。

## 6. 非目标

- 地点、坐标、事件或时间线的独立数据模型；
- 多周目管理；
- 实时聊天、匿名评论或 WebSocket 推送；
- 通用 CMS、地图引擎、复杂动画框架；
- 玩家排行、在线状态和服务器运维功能。

## 7. 验收要点

- 新上传并发布的照片可通过动态公开 API 在刷新后看到；
- 普通用户不需要填写照片、作品集或区块 ID；
- 作品集图片选择显示最新照片标题，不暴露媒体 ID 作为主要操作方式；
- 公开页面和 API 不存在地点/事件独立入口或实体字段；
- MySQL 中不存在地点、事件及其关联表；
- 内容校验、类型检查、单元测试、静态生成和浏览器测试通过。
