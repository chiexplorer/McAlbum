# McAlbum 数据备份与恢复

本文面向已按 `docs/部署说明.md` 运行的 Ubuntu 单机环境。备份可以使用脚本重复执行；正式恢复会覆盖数据库和媒体文件，必须逐步操作。

## 1. 备份范围和数据定位

McAlbum 的完整运行状态由三部分组成：

| 内容 | 位置 | 恢复价值 |
| --- | --- | --- |
| 业务数据 | MySQL 数据库 `mcalbum` | 用户、权限、照片、动态作品集、评论和实体关系 |
| 媒体文件 | `storage/originals` 和 `storage/variants` | 上传原图和网页展示变体 |
| 静态发布物 | `apps/web/.output/public` | 快速恢复当时对外发布的网页 |

项目代码、数据库迁移和内置作品集由 Git 保管。`content/photos/`、`content/stories/` 和 `apps/web/app/generated/` 中的动态 JSON 是 MySQL 的公开快照，可以重新生成，不是首要备份源。

备份脚本会生成：

```text
backups/YYYYMMDD-HHMMSS/
├── mcalbum.sql.gz       # MySQL 逻辑备份
├── media.tar.gz        # 原图和公开变体
├── web-static.tar.gz   # 静态前端，存在时生成
└── SHA256SUMS          # 完整性校验
```

### 执行前提

- 使用 `root` 账号；
- MySQL 处于运行状态；
- `/etc/mysql/mcalbum-backup.cnf` 中的账号密码已验证可用；
- 项目根目录为 `/root/McAlbum`，如果实际路径不同，按实际路径替换。

验证 MySQL 备份账号：

```bash
mysql --defaults-file=/etc/mysql/mcalbum-backup.cnf -D mcalbum -e "SELECT CURRENT_USER(), DATABASE();"
```

## 2. 手动完整备份

手动流程用于理解备份的每一部分。为避免备份数据库时恰好又有用户上传文件，完整备份期间短暂停止 FastAPI。静态页面仍可继续由 Nginx 提供。

### 2.1 创建备份目录

```bash
export PROJECT_ROOT="$(cd /root/McAlbum && pwd -P)" && export BACKUP_ID="$(date +%Y%m%d-%H%M%S)" && export BACKUP_DIR="$PROJECT_ROOT/backups/$BACKUP_ID" && install -d -m 0700 "$BACKUP_DIR" && echo "$BACKUP_DIR"
```

### 2.2 停止 FastAPI

```bash
systemctl stop mcalbum-api
```

从本步开始，无论后续命令是否成功，结束操作前都必须执行 2.7 节重新启动 FastAPI。

### 2.3 导出 MySQL

```bash
set -o pipefail && mysqldump --defaults-file=/etc/mysql/mcalbum-backup.cnf --single-transaction --quick --routines --triggers --events --hex-blob --no-tablespaces --set-gtid-purged=OFF --default-character-set=utf8mb4 mcalbum | gzip -9 > "$BACKUP_DIR/mcalbum.sql.gz"
```

### 2.4 打包媒体文件

```bash
tar -C "$PROJECT_ROOT" -czf "$BACKUP_DIR/media.tar.gz" storage/originals storage/variants
```

### 2.5 打包静态前端

已经完成正式构建时执行：

```bash
tar -C "$PROJECT_ROOT/apps/web/.output" -czf "$BACKUP_DIR/web-static.tar.gz" public release-manifest.json
```

如果尚未生成 `release-manifest.json`，只打包可部署页面：

```bash
tar -C "$PROJECT_ROOT/apps/web/.output" -czf "$BACKUP_DIR/web-static.tar.gz" public
```

### 2.6 生成并验证校验和

```bash
cd "$BACKUP_DIR" && sha256sum mcalbum.sql.gz media.tar.gz web-static.tar.gz > SHA256SUMS && gzip -t mcalbum.sql.gz && tar -tzf media.tar.gz >/dev/null && tar -tzf web-static.tar.gz >/dev/null && sha256sum -c SHA256SUMS
```

所有项目应显示 `OK`。如果未备份静态前端，从命令中移除 `web-static.tar.gz` 及对应的 `tar -tzf` 检查。

### 2.7 恢复 FastAPI

```bash
systemctl start mcalbum-api && systemctl is-active mcalbum-api && curl --fail --silent --show-error http://127.0.0.1:8000/api/health && echo
```

## 3. 使用一键备份脚本

脚本位于 `deploy/scripts/backup-mcalbum.sh`，会执行第 2 节的完整流程，并具备以下保护：

- 检查项目、MySQL 配置和媒体目录；
- 使用文件锁防止两个备份同时运行；
- 导出期间短暂停止 FastAPI；
- 脚本成功、失败或被中断时都尝试恢复 FastAPI；
- 自动校验 gzip、tar 和 SHA-256。

在项目根目录执行：

```bash
bash deploy/scripts/backup-mcalbum.sh "$PROJECT_ROOT"
```

脚本完成后会输出备份目录和各文件大小。再次人工复核：

```bash
cd "$PROJECT_ROOT/backups/替换为备份目录" && sha256sum -c SHA256SUMS
```

## 4. 备份恢复

正式恢复前必须先完成测试恢复。恢复文件必须与当时的 Git 版本对应；如果代码已经更新，数据库恢复后再通过 Alembic 升级到当前版本。

### 4.1 设置恢复变量并校验备份

```bash
export PROJECT_ROOT="$(cd /root/McAlbum && pwd -P)" && export RESTORE_DIR="$PROJECT_ROOT/backups/替换为备份目录" && test -f "$RESTORE_DIR/mcalbum.sql.gz" && test -f "$RESTORE_DIR/media.tar.gz" && cd "$RESTORE_DIR" && sha256sum -c SHA256SUMS
```

### 4.2 恢复到测试数据库

测试数据库不覆盖正在使用的 `mcalbum`：

```bash
mysql -e "DROP DATABASE IF EXISTS mcalbum_restore_test; CREATE DATABASE mcalbum_restore_test CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;"
```

导入备份：

```bash
set -o pipefail && gzip -dc "$RESTORE_DIR/mcalbum.sql.gz" | mysql mcalbum_restore_test
```

检查表数量和 Alembic 版本：

```bash
mysql -NBe "SELECT COUNT(*) FROM information_schema.tables WHERE table_schema='mcalbum_restore_test'; SELECT version_num FROM mcalbum_restore_test.alembic_version;"
```

验证媒体包可解压，不覆盖生产目录：

```bash
export MEDIA_TEST_DIR="$(mktemp -d /tmp/mcalbum-media-restore.XXXXXX)" && tar -C "$MEDIA_TEST_DIR" -xzf "$RESTORE_DIR/media.tar.gz" && test -d "$MEDIA_TEST_DIR/storage/originals" && test -d "$MEDIA_TEST_DIR/storage/variants" && echo "媒体测试恢复成功：$MEDIA_TEST_DIR"
```

确认测试结果后，可删除临时测试数据库：

```bash
mysql -e "DROP DATABASE mcalbum_restore_test;"
```

### 4.3 正式恢复前的强制检查

正式恢复会删除当前 `mcalbum` 数据库。执行前逐项确认：

- 4.2 节的测试恢复已成功；
- 已经对当前生产现场再执行一次第 3 节备份；
- `RESTORE_DIR` 指向的时间和备份内容正确；
- 已经确认要恢复的 Git 版本。

再次显示绝对路径：

```bash
realpath "$PROJECT_ROOT" && realpath "$RESTORE_DIR" && ls -lh "$RESTORE_DIR"
```

### 4.4 停止 FastAPI 并恢复 MySQL

```bash
systemctl stop mcalbum-api
```

以下命令会删除当前生产数据库，仅在已完成 4.3 节检查时执行：

```bash
mysql -e "DROP DATABASE mcalbum; CREATE DATABASE mcalbum CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;"
```

导入数据：

```bash
set -o pipefail && gzip -dc "$RESTORE_DIR/mcalbum.sql.gz" | mysql --defaults-file=/etc/mysql/mcalbum-backup.cnf mcalbum
```

### 4.5 恢复媒体

不直接删除现有媒体，先将它们移入现场保留目录：

```bash
export STORAGE_STASH="$PROJECT_ROOT/storage-before-restore-$(date +%Y%m%d-%H%M%S)" && test -d "$PROJECT_ROOT/storage/originals" && test -d "$PROJECT_ROOT/storage/variants" && install -d -m 0700 "$STORAGE_STASH" && mv -- "$PROJECT_ROOT/storage/originals" "$PROJECT_ROOT/storage/variants" "$STORAGE_STASH/"
```

解压备份：

```bash
tar -C "$PROJECT_ROOT" -xzf "$RESTORE_DIR/media.tar.gz"
```

恢复权限：

```bash
chown -R root:www-data "$PROJECT_ROOT/storage/originals" "$PROJECT_ROOT/storage/variants" && chmod -R u=rwX,g=rX,o= "$PROJECT_ROOT/storage/originals" "$PROJECT_ROOT/storage/variants"
```

### 4.6 恢复或重建静态前端

如果备份包含 `web-static.tar.gz`，并且需要精确恢复当时页面，先保留当前产物：

```bash
test -f "$RESTORE_DIR/web-static.tar.gz" && export WEB_STASH="$PROJECT_ROOT/apps/web/output-before-restore-$(date +%Y%m%d-%H%M%S)" && test -d "$PROJECT_ROOT/apps/web/.output" && mv -- "$PROJECT_ROOT/apps/web/.output" "$WEB_STASH" && install -d -m 0750 "$PROJECT_ROOT/apps/web/.output" && tar -C "$PROJECT_ROOT/apps/web/.output" -xzf "$RESTORE_DIR/web-static.tar.gz"
```

恢复旧静态产物后授予 Nginx 读取权限：

```bash
test -d "$PROJECT_ROOT/apps/web/.output/public" && setfacl -R -m u:www-data:rX "$PROJECT_ROOT/apps/web/.output/public"
```

如果不恢复旧静态产物，则在数据库和媒体恢复后，按 `docs/部署说明.md` 第 8 节使用当前代码重新生成。

### 4.7 升级数据库结构

如果当前代码比备份时更新，执行 Alembic：

```bash
set -a && source /etc/mcalbum/api.env && set +a && cd "$PROJECT_ROOT/apps/api" && .venv/bin/alembic -c alembic.ini upgrade head && .venv/bin/alembic -c alembic.ini current
```

### 4.8 启动并验收

```bash
systemctl start mcalbum-api && systemctl is-active mcalbum-api && curl --fail --silent --show-error http://127.0.0.1:8000/api/health && echo
```

检查 MySQL 和媒体数量：

```bash
mysql --defaults-file=/etc/mysql/mcalbum-backup.cnf -NBe "SELECT 'users', COUNT(*) FROM mcalbum.users UNION ALL SELECT 'media_assets', COUNT(*) FROM mcalbum.media_assets UNION ALL SELECT 'photos', COUNT(*) FROM mcalbum.photos UNION ALL SELECT 'stories', COUNT(*) FROM mcalbum.stories UNION ALL SELECT 'comments', COUNT(*) FROM mcalbum.comments;" && find "$PROJECT_ROOT/storage/originals" -type f | wc -l && find "$PROJECT_ROOT/storage/variants" -type f | wc -l
```

最后通过网页人工检查登录、相册、作品集、原图下载和评论。
