# McAlbum 实施计划

## 1. 实施目标

以轻量方式完成一个可长期维护的 Minecraft 世界档案馆：照片可上传、编目、审核和动态公开；作品集可通过可视化区块组织；玩家拥有简单、可靠的账号与权限边界。

项目时区固定为 `Asia/Shanghai`。业务时间在数据库保存为 UTC，显示时转换为北京时间。

## 2. 当前范围

当前实体包括媒体、照片、作品集、玩家、用户、评论和审计记录。项目只记录一个持续世界，不维护周目、地点或事件实体。

地点和事件背景仍可写入照片说明、标签、作品集标题和正文。若未来内容规模足以支撑结构化查询，再通过新需求和新迁移重新评估；当前不预留数据库空表、API 字段或管理入口。

## 3. 素材处理约定

- 临时参考图经导入脚本进入 `storage/originals`，不直接引用临时目录；
- 浏览器只访问 `storage/variants` 中的公开变体；
- 原文件名只作为元数据，磁盘 storage key 由系统生成；
- 文件名如 `2026-09-06_17.16.37.png` 时解析拍摄日期，否则默认北京时间当前日期；
- 无法确认的玩家身份、作者和历史事实使用中性描述，不虚构归因。

## 4. 纵向切片顺序

每个阶段都同时关注契约、数据、页面和验证，避免只完成孤立界面。

### 5.1 工程与契约基线（已完成）

- 初始化 Nuxt、FastAPI、MySQL、JSON Schema、Zod 和测试结构；
- 固定 Node/Python 命令、时区和目录边界；
- 建立内容校验与浏览器安全投影。

### 5.2 媒体导入（已完成）

- 导入参考图片，保存原图并生成响应式 WebP 变体；
- 记录尺寸、哈希、焦点、替代文本和处理状态；
- 页面不暴露原图路径或内部文件信息。

### 5.3 首页与相册（已完成）

- 完成服务器简介、共同游玩原则、近期照片和代表作品；
- 完成标签筛选、URL 状态、响应式网格和图片查看器；
- 裁切由容器比例、`object-fit: cover` 和焦点坐标自适应完成。

### 5.4 作品集与玩家志（已完成）

- 完成作品集列表、详情和多类内容区块；
- 完成玩家列表、详情模板与私密状态过滤；
- 当前长内容由静态 JSON 快照提供。

### 5.5 发布与质量门禁（已完成）

- 完成 Canonical、Open Graph、robots、sitemap 和定制 404；
- 完成内容校验、类型检查、单元测试、静态产物检查与 Playwright 回归；
- 建立发布清单和原图备份约定。

### 5.6 公开内容边界（已完成）

- 自动生成浏览器安全媒体与内容投影；
- 过滤私密玩家、隐藏评论和内部元数据；
- 页面不直接读取完整源 JSON 或原图清单。

### 5.7 玩家协作与动态照片（已完成）

- FastAPI 会话认证、邀请注册、固定能力和审计；
- 照片上传与散图编目采用同页流程，同时保留独立媒体库用于恢复和存量查看；
- 作品集编排、本人档案和评论管理；
- 照片与作品集状态流转；
- 本地文件系统 + MySQL 元数据；
- 公开照片列表和详情动态 API，发布后刷新页面即可看到，无需重启或重建前端。

### 5.8 单世界内容模型精简（已完成）

- 删除周目相关字段和实体；
- 删除地点、事件、时间线页面、管理入口、权限和静态契约；
- Alembic `20261028_0003` 删除地点/事件表、关联表和 `photos.place_id`；
- 照片、作品集和区块 ID 全部由系统生成；
- 作品集封面和区块图片改为按最新照片标题选择；
- 相关照片改按主题标签匹配。

## 5. 后续建议

### 近期

- 用真实账号完整走通上传并保存草稿 → 审核/发布 → 刷新公开页面；
- 继续完善作品集动态公开后的加载提示和异常状态；
- 增加媒体标题搜索，避免照片数量增长后下拉过长；
- 完善备份、恢复和部署脚本。

### 按真实需求再评估

- 作品集动态公开 API；
- 照片分页和标签服务端筛选；
- 更多玩家授权资料；
- 只有当地点或事件达到稳定、可维护的内容规模时，才重新提出独立实体方案。

## 6. 完成标准

- 数据库迁移头为 `20261028_0003`，不存在地点/事件及关联表；
- 管理端没有地点、事件、周目或手工 ID 字段；
- 作品集图片选择展示照片标题；
- 公开页面没有地点/时间线路由或失效链接；
- Ruff、pytest、内容校验、前端类型检查、Vitest、静态生成和 Playwright 测试全部通过；
- 文档、OpenAPI、JSON Schema 和实现保持一致。
