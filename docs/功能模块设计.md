# McAlbum 功能模块设计

## 1. 总体原则

功能以浏览舒适、内容可保存和维护成本低为优先。页面通过 repository/service 访问数据；公开浏览采用静态页面骨架与动态照片 API，管理功能通过 FastAPI 完成。

当前领域实体只有媒体、照片、作品集、玩家、用户、评论和审计记录。地点与事件只作为叙事文字存在，不建立独立模块。

## 2. 公开浏览

### 世界首页

展示服务器简介、共同游玩原则、代表作品集与近期照片。动态照片 API 可用时显示最新发布内容，不可用时回退到构建快照。

### 相册

以响应式网格展示照片，支持标签筛选、稳定详情 URL 和键盘可用的大图查看。图片使用焦点坐标配合 `object-fit: cover`，更换素材后布局保持稳定。

### 照片详情

展示标题、日期、说明、标签、作品集关系、相关标签照片和评论。相关照片按标签交集计算，不依赖地点实体。

### 历史作品集

作品集列表与详情负责完整历史叙事。内容区块按数组顺序渲染：

- `text`：正文；
- `wide-image`：宽幅图片与说明；
- `image-grid`：多图组合；
- `text-with-image`：图文并排；
- `player-quote`：经授权的玩家引语。

### 玩家志

公开玩家列表只包含非私密档案；详情展示简介、加入时间、头像和代表作品。

## 3. 管理端

### 照片上传与编目

日常入口将原图上传与散图编目合并在同一表单中。用户选择新文件，填写替代文本、标题、说明、日期、标签和版式，一次提交后依次完成媒体入库与照片草稿创建。替代文本自动填入标题；拍摄日期优先从文件名解析，否则默认北京时间当前日期，自动值均可继续修改。

用户也可以从媒体库选择已经入库但尚未编目的图片。媒体库作为处理状态、失败恢复和存量图片查看入口保留，不要求普通投稿者先在两个页面之间切换。媒体 ID 与照片 ID 均由 FastAPI 自动生成，表单不提供 ID、周目、地点或事件字段。

### 作品集编排

用户填写标题与摘要，通过最新照片标题下拉选择封面和区块图片。图片网格使用多选列表。作品集 ID 和新区块 ID 均由服务端生成；编辑已保存区块时保留原区块 ID。

“区块”是作品集正文的最小可排序单元。区块 ID 只用于可靠更新和追踪，不是内容名称，也不要求玩家理解或填写。

### 玩家档案

普通用户只能编辑绑定到自己账号的玩家资料；管理员不能通过删除账号级联删除历史档案。

### 权限与审核

固定角色配合固定能力标识。普通用户只能修改本人草稿或退回内容；发布能力与投稿能力分离。所有权、状态转换和公开字段过滤由 API 校验。

## 4. 数据刷新策略

- 首页、相册和照片详情在客户端请求 `/api/public/photos`；
- 上传、编目并发布后，访客刷新页面即可看到新照片，无需重新运行前端；
- API 不可用时保留静态快照，保证基本浏览；
- 作品集列表和详情同样由公开 API 动态同步；静态重建只更新首屏兜底和 SEO 快照。

## 5. 可访问性与异常状态

- 所有表单控件有可读标签；
- 加载、空状态、API 不可用和权限不足使用明确文案；
- 键盘焦点可见，查看器支持 Escape；
- 动画遵循减少动态效果设置；
- 触控目标和移动端排版满足舒适操作。

## 6. 当前明确不实现

- 地点档案、地点选择、坐标管理和地图；
- 事件投稿、事件权限、时间线和事件关联；
- 手工填写照片、作品集、区块或媒体 ID；
- 实时协作、实时评论、通用角色编辑器。
