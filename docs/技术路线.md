# McAlbum 技术路线

## 1. 架构结论

采用“Nuxt 静态前端 + FastAPI 动态 API + MySQL + 本地媒体文件系统”。公开页面保留静态快照和 SEO 能力，照片列表与详情通过公开 API 动态刷新；投稿、审核、权限和上传全部走 FastAPI。

项目只维护一个持续世界。当前不建模周目、地点和事件；数据库、API、JSON Schema、Zod 和页面路由均不保留这三类实体的兼容字段。

## 2. 前端

- Nuxt 4、Vue 3、TypeScript；
- Zod 校验公开 JSON 与 API 响应；
- Nuxt Image 与自有媒体组件生成响应式图片；
- 原生 CSS/CSS Variables；
- Vitest 与 Playwright；
- repository/service 隔离 JSON 快照和动态 API。

公开路由为 `/`、`/album`、`/photos/:id`、`/stories`、`/stories/:id`、`/players` 和 `/players/:id`。管理路由包含登录、媒体、照片、作品集、玩家资料、用户权限和评论管理。

## 3. 内容契约

结构化静态内容使用 JSON，位于 `content/`：

```text
content/
├── site.json
├── media-assets/
├── photos/
├── stories/
└── players/
```

权威 Schema 位于 `contracts/json-schema/`，Zod 是运行时镜像。字段变更必须同步修改两者和契约测试。

照片、作品集和区块均使用不可变稳定 ID。照片采用 `photo-<uuid>`，作品集采用 `story-<uuid>`，区块采用 `section-<uuid>`；创建时由 FastAPI 生成。媒体使用内部 `media-<uuid>`，管理界面通过照片标题选择媒体，不让用户手工录入。

## 4. FastAPI

分层为 Router → Service → Repository → SQLAlchemy/File Storage。

- `/api/manage/media`：上传与媒体元数据；
- `/api/manage/photos`：照片草稿、更新和状态转换；
- `/api/manage/stories`：作品集草稿、更新和状态转换；
- `/api/manage/profile`：本人玩家资料；
- `/api/public/photos`：动态公开照片列表与详情；
- `/api/public/stories`：动态公开作品集列表与详情；
- `/api/admin/*`：注册审核、角色权限、账号封禁、评论删除和静态重建。

公开 API 只返回 `published` 内容和浏览器安全媒体变体。认证使用服务端会话与 `HttpOnly`、`Secure`、`SameSite` Cookie，密码使用 Argon2id。

## 5. MySQL

生产、开发和集成测试统一使用 MySQL，表使用 InnoDB 与 `utf8mb4`。核心表包括：

- `users`、`roles`、`permissions`、`role_permissions`、`user_sessions`；
- `players`；
- `media_assets`、`media_variants`；
- `photos`、`stories`、`comments`；
- `photo_players`、`photo_stories`、`story_players`；
- `audit_logs`。

作品集 `sections` 使用 MySQL JSON，以保持区块结构灵活；核心关系继续使用普通列、外键和关联表。

迁移 `20261028_0003` 删除 `places`、`timeline_events`、六张地点/事件关联表以及 `photos.place_id`，并清理 `event.*` 权限。未来如需求重新成立，应通过新的 Alembic 迁移重新设计，而不是恢复前端隐藏字段。

## 6. 媒体存储

- `storage/originals`：原图，必须备份；
- `storage/variants`：公开 WebP 变体；
- `storage/temporary`、`storage/quarantine`：非公开处理区；
- 数据库只保存相对 storage key 和元数据，不保存 BLOB 或绝对路径；
- Nginx 提供公开变体，FastAPI 负责上传、校验、处理和元数据。

媒体写入以 `pending`、`ready`、`failed`、`deleted` 状态处理文件系统与数据库的非原子一致性。

使用 `python -m app.cli cleanup-missing-media` 只读检查数据库媒体元数据与本地文件；确认后增加 `--apply --actor <管理员用户名>`，以软删除方式隔离缺图内容并同步静态 JSON 快照。

## 7. 发布与验证

日常发布照片或作品集不要求重建前端；刷新页面后由公开 API 获取。静态重建只用于刷新 SEO 首屏、故障兜底快照和归档。

最低验证集：

```powershell
npm run validate:content
npm run typecheck:web
npm run test:web
python -m ruff check apps/api
python -m pytest apps/api
```

合并前运行 `npm run check:web`，正式发布前设置 `NUXT_PUBLIC_SITE_URL` 并运行 `npm run check:release`。
